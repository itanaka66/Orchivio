# Installable Studio (PWA, FR-129)

The Studio (`apps/web`) is a **progressive web app**: it can be installed from the browser ("Install Studio as an app"), starts in its own
window, adapts to small screens and safe areas, opens its shell without a connection, and tells people when it is offline or when a new version is
ready. This is the **PWA** half of FR-129; offline *data* and sync (P2) are not built.

## What is cached, and what never is

The service worker (`apps/web/public/sw.js`) caches only the **app shell**: the page, the content-hashed build assets, the icons, the manifest and an offline
page. **It never answers from, or stores, anything under `/api/`, `/healthz`, `/readyz` or `/metrics`**, never handles non-GET requests or other origins, and
skips responses that are not plain 200s or that say `Cache-Control: no-store`. No application data, token or session detail is left on the device, and signing
out also asks the worker to clear its caches. Offline, an API call simply fails and the Studio shows the server's/transport's error plus an "offline" bar.

* Pages: **network first** (so a new release shows up), the cached shell when there is no network, the offline page if there is no cached shell.
* `/assets/*` and `/icons/*`: **cache first** (they are content-hashed or static).
* Updates: every release stamps a new id into `sw.js` (`pwa-plugin.ts`, from a hash of the built `index.html`), so browsers see a changed worker. A new worker
  **waits**; the Studio shows "A new version is ready. Reload to update" and only takes over when the person clicks, so a reload is never forced in the
  middle of editing a flow (unsaved edits would be lost).

## Serving it

Serve `dist/` from the same origin as the API, over **HTTPS** (browsers only install and run service workers on secure origins; `localhost` is exempt).
Recommended headers for the reverse proxy:

| Path | Header |
|---|---|
| `/sw.js` | `Cache-Control: no-cache` (the worker file must not be HTTP-cached; the registration also passes `updateViaCache: 'none'`) |
| `/index.html`, `/manifest.webmanifest`, `/offline.html` | `Cache-Control: no-cache` |
| `/assets/*` | `Cache-Control: public, max-age=31536000, immutable` |
| `/manifest.webmanifest` | `Content-Type: application/manifest+json` |

The worker is registered only in production builds (`import.meta.env.PROD`), never by the dev server.

## Files

`public/manifest.webmanifest` (name, standalone display, colours, 192/512 and maskable icons), `public/icons/*.png` (generated by `scripts/make_pwa_icons.py`,
no image library needed; a test fails if they drift), `public/sw.js`, `public/offline.html`, `src/pwa/` (registration, `usePwa`, `PwaBar`), `pwa-plugin.ts`.

## Not built

Offline data, background sync and conflict handling (P2), push notifications, a service worker for *generated applications* (their UI renderer does not exist yet),
share targets and shortcuts, and screenshots in the manifest. Install prompts and the install experience differ per browser and were not tried on real devices.
