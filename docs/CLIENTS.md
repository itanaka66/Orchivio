# Typed clients (FR-031)

Orchivio generates a **typed TypeScript client** for the data API of an application, from its model.

```bash
orchivio client model.yaml -o src/inventory-client.ts      # from a model file
curl -OJ -b cookies /api/v1/revisions/<revision-id>/client.ts   # from a stored revision (needs model.read)
```

The file is a single dependency-free module (it only needs `fetch`). It is built from the same OpenAPI document as `orchivio openapi`
(docs/MODEL-SPEC.md, `tests/integration/test_openapi.py` checks that document against real API responses), so:

* an interface per persistent entity with the model's field types: `integer` → `number`, enums → string unions, `decimal` → `number | string`,
  `uuid`/`date`/`date-time` → `string` (the format is in the doc comment), computed and generated fields are `readonly`;
* `…Create` and `…Update` input types with the required fields of the model (a computed or generated field cannot be sent: it is a compile error);
* only operations **at least one role may perform** exist (an entity nobody can delete has no `delete`); which role may do what remains the
  server's decision, and its `403`/`404` come back as errors;
* `list` takes typed `limit`, `offset`, `orderBy` (the stored fields), `desc` and equality `filter`s;
* errors are an `OrchivioApiError` with `status`, `code`, `message` and `details` from the server's error envelope, also for non-JSON error pages;
* the header comment carries the model hash, so a stale client can be told from a current one.

```ts
import { OrchivioDataClient } from './inventory-client'

const api = new OrchivioDataClient({
  baseUrl: '/api/v1/applications/<id>/preview',          // where the data API is served
  headers: () => ({ 'X-Preview-User': 'u1', 'X-Preview-Roles': 'admin' }),   // or an access token
  credentials: 'include',
})
const page = await api.product.list({ orderBy: 'name', filter: { sku: 'B-1' } })
const made = await api.product.create({ name: 'Bolt', sku: 'B-1', quantity: 3, reorder_level: 1 })
await api.product.update(made.id, { quantity: 9 })
```

## How it is kept honest

* the generator is a pure translation of the OpenAPI document; a table test covers every schema construct;
* a test compiles a generated client with `tsc --strict` together with usage code, and requires wrong use (a string for a number, a missing required field,
  an unknown field, a read-only field, a field that is not sortable) to be compile errors;
* a test replays the client's requests (paths, query names, body shape) against the real preview API;
* the client for the example model is checked in at `apps/web/src/generated/inventory-client.ts` (regenerated by `scripts/export_web_contract.py`,
  failing `tests/unit/test_web_contract.py` when stale) and is type-checked and tested with the web build.

## Not generated

Flow runs and process starts (they are not part of the data API's OpenAPI document), pages, authentication and token refresh (supply `headers`),
other languages, and a client for the platform (Studio) API, which the Studio's own hand-written `ApiClient` covers.
